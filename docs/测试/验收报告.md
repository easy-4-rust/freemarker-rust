## 3. 本轮新增（对比 v2）

- **P1 解析器补全（智能体 F 产出）**：`<#foreach>`、`<#items as x>` 循环变量、多赋值、双循环变量 `as k, v`、多 body 参数、多参数 lambda、`.namespace`/`.locale`/`.output_encoding` 等内置变量、`?switch`/`?then` 惰性条件——18 个用例从 SKIP 转 PASS
- **P4 格式化（智能体 G 产出）**：ISO 日期格式化 1,108 行（对齐 ISOLikeTemplateDateFormat）、Java 模式日期 31KB、DecimalFormat 模式、输出编码（output-encoding1 转 PASS）——dateformat 全家族 5 用例转 PASS
- **P5 pyo3 桥（智能体 H 产出）**：`freemarker-pyo3` crate（wrapper/models/bridge/errors/lib 5 文件，对应 JythonWrapper/JythonModel 家族/TemplateModelToJythonAdapter）——wrap/unwrap 类型矩阵、双通道 getattr/get_item、GIL 单次持有、unsendable pyclass、PyErr↔TemplateError 桥接；Rust 33 测试 + Python pytest 22 用例全绿
- **trim 专项（v2 完成）**：以官方 freemarker-2.3.34.jar 实测为权威 oracle（Probe8-19 系列），逐项对齐 Java `TextBlock.postParseCleanup` 语义：
  - **prev/next 链多跳**：`openingCharsToStrip`/`trailingCharsToStrip` 的 prevTerminalNode/nextTerminalNode 链不止一跳——`  ${""}<@x/><#lt>\n` 的 `\n` 须穿过 Trim(heeds=false) 与 Call(heeds=false) 直达 Interp(heeds=true) 才判定不剥
  - **ignorable 感知**：全空白文本夹在非输出元素之间（或空文本）时 heeds=false（Java `isIgnorable` → `heeds*Whitespace=false`），链继续穿过；`remove_ignorable` 在每层清理后移除 ignorable 元素（含 TrimInstruction）
  - **解析期立即应用**：剥离在解析期直接改写文本（Java `text = substring`），后续链所见即最终内容
  - **Java 执行顺序**：deliberateLeftTrim 先、deliberateRightTrim 后，自动剥离作用于裁剪后文本；HEINOUS 块（trailing 全空白时按后文同行 heeds/`<#lt>` 判定）；rt 裁掉首行后 beginColumn=1 的 trailing 剥离条件
  - **?int/?long/?byte/?short 溢出回绕**（Java `intValue()`/`byteValue()` 原始类型强转语义）
  - **DecimalFormat 快路径**：Float/Double 以最短往返表示为基准按 max_frac 舍入（Float 先加宽 Double）；比较/算术的 toBigDecimal 用 toString 最短表示
  - **`<#setting whitespace_stripping=...>` 解析期拒绝**（Java PropertySetting 配置级设置白名单）
- **BLOCKED 推进（本轮，5 用例转 PASS）**：以官方 jar 实测为 oracle（Probe8-20/8-21 系列）：
  - **?interpret**：`Interpret.java` 语义——`getWriter → env.include` 返回透传 writer、body 直通；`<#transform>`（TransformBlock → visitAndTransform：TransformControl 的 onStart/afterBody/REPEAT_EVALUATION 流程）；UnifiedCall 对 `TemplateTransformModel` 的分支（exec_call，调用产物在宏命名空间可见）；interpret.ftl 逐字节一致
  - **?eval**：`BuiltInsForStringsMisc.evalBI` 语义——`(...)` 包装按表达式解析、失败包装 `Failed to "?eval" string with this error: ... The failing expression:` 双错误通道
  - **范围切片**：`DynamicKeyName.dealWithRangeKey` 完整语义——空有界范围→空结果、负起始报错、自适应（`..*` size-limited 与无界）越界裁剪、起始越界规则（自适应递增可 == 长度，其余 >= 即错）、字符串降序 resultSize>1 报错、空范围不查界——range-lazy/lastcharacter/listliteral 转 PASS
- **BLOCKED 推进（本轮，range-ici 系列 2 用例转 PASS）**：以 Java 源码逐行核对 + golden 双 ICI 实测（Probe8-21 系列续）：
  - **旧版 string-slicing bug 模拟**（DynamicKeyName.java:322-330）：`isAffectedByStringSlicingBug = inclusiveEnd`（BoundedRangeModel.java:40-41，仅 `a..b` 闭区间；`..<`/`..!`/`..*` 不受影响）——字符串降序切片结果长为 2 时返回 "" 而非报错（`s[1..0]`/`s[2..1]` == ""，`s[3..1]`/`s[3..<1]`/`s[3..*-2]` 报 decreasing）
  - **ICI 门控右无界范围**（Range.java:44-47）：ICI ≥ 2.3.21 → Listable（序列角色 size=Integer.MAX_VALUE、`r[i]`=begin+i、`(4..)?size`==2147483647）；< 2.3.21 → NonListable（size=0、迭代为空、`(4..)?size`==0）
  - **数字键负下标按 Java 分发**（DynamicKeyName.java:98-147）：范围目标 → RangeModel.get 的 "Range item index -1 is out of bounds."；SimpleSequence 越界 → null（invalid reference）；字符串目标 → "Negative index not allowed"
  - **惰性列表迭代**（IteratorBlock.java:278-322 集合优先）：`PendingItems` 惰性拉取——`<#list (4..) as i>` 不物化 2^31-1 项，has_next 前视 peek 语义——range-ici-2.3.20/2.3.21 全部断言（range-common.ftl 315 行 + 两用例文件）逐条通过
  - **jar 探针核对（Probe22，官方 freemarker-2.3.34.jar 双 ICI 实测 14 项全对齐）**：`s[1..0]`/`s[2..1]` == ""（两 ICI 均模拟）、`s[3..1]`/`s[3..<1]`/`s[3..*-2]` 报 decreasing（first/last 数字一致）、`s[0..*-1]` == "a"、`(4..)?size` == 0 / 2147483647（ICI 门控）、`(4..)[-1]` == "Range item index -1 is out of bounds."（两 ICI）、`(4..)[0]` @2.3.20 == "has evaluated to null or missing"
- **?join 集合支持（本轮，list2 转 PASS）**：验证器点名的引擎缺口——Java `joinBI` 全语义（BuiltInsForSequences.java:191-265）：
  - **集合优先**：TemplateCollectionModel → 惰性迭代器；其次 TemplateSequenceModel（:251-263）；`listables.iterator`/`getIterator` 等集合模型可直接 `?join`
  - **1-3 参数**：separator / whenEmpty / afterLast（checkMethodArgCount(args, 1, 3)，`_MessageUtil.newArgCntError` 消息逐字对齐："...but has received none./{n}."）
  - **null 项跳过**（:225 `if (item != null)`，idx 仍递增）；**逐项错误包装**（:230-238）：`"?join" failed at index {idx} with this error:` + EMBEDDED_MESSAGE_BEGIN/END（"---begin-message---\n"/"\n---end-message---"）
  - **右无界数值范围守卫**（:929-935 checkNotRightUnboundedNumericalRange）：`(1..)?join(',')` 报 "The input sequence is a right-unbounded numerical range, thus, it's infinitely long, and can't processed with this built-in."
  - **jar 探针核对（Probe23，8 项全对齐）**：null 跳过 "a-b"、三参数 "a-bLAST"/"EMPTY"、惰性集合 ?map 直连 "x,y,z"、右无界守卫/失败索引/参数数量消息逐字一致
- **string 家族修复（本轮，string-builtins1 归因、string-builtins3 定位为过期断言）**：
  - **?substring 越界语义**（BuiltInsForStringsBasic.java:609-662）：负下标/越界按 Java 顺序报错（"The index must be at least 0, but was -1." / "The index mustn't be greater than the length of the string, 2, but it was 3." / "The begin index argument, 1, shouldn't be greater than the end index argument, 0."）；参数数量 1-2（Probe24 逐字核对）——原实现 `.max(0)` 静默截断负下标，string-builtins1 行 27 的 assertFails 直接暴露
  - **参数数量消息逐字对齐**（_MessageUtil.newArgCntError）："?{name}(...) expects 1 or 2 arguments but has received none./{n}."（max-min==1 时 "or"；min==max 时单数；0 参数 "none"）——string-builtins3 的 'none'/'3'/'4' 断言
  - **?keep_before_last/?keep_after_last 正则重叠扫描**：Java `matcher.find(start+1)` 重叠推进；fancy_regex 的 find_iter 不重叠会漏匹配（"aaabb" 上 `[ab]{3}` → "aaa"@0/"aab"@1/"abb"@2，非重叠只给 "aaa"@0）——`last_regexp_match` 按字符边界前进（Probe27 核对）
  - **?ensure_starts_with 默认正则**（:163-166）：2 参数无显式 flags → RE_FLAG_REGEXP（lookingAt 锚定开头）；?ensure_ends_with 收紧为 Java 的 1 参数（:123-145 checkMethodArgCount(args, 1)）
  - **?lower_abc/?upper_abc 精确整数**（abcBI → NumberUtil.toIntExact）：非整数值报 "Can't convert 1.00001 to type Integer without loss."；≤0 报 "must be at least 1, but was {n}."（Probe24/26 逐字核对）
- **assignments 转 PASS（本轮）**：Java `AddConcatExpression` + `Assignment` 全语义（Probe28/29/30 实测）：
  - **序列拼接**：双序列 → `ConcatenatedSeq` 懒惰拼接（size=左+右、get 委派、迭代器链式，:79-83）——`x = [11]` 后 `x += [22]` → [11, 22]
  - **哈希合并**：双哈希 → 物化合并（键序左在前、右键追加；碰撞右值胜出——IndexMap 语义与 Java `ConcatenatedHashEx` 一致）；非 ex 哈希 → `CombinedHash` 惰性右优先查找包装
  - **复合赋值错误消息逐字对齐**（Assignment.java:156-162 + NonNumericalException）：目标缺失 → "The target variable of the assignment, \"{target}\", was null or missing in the template namespace, and the \"{op}\" operator must get its value from there before assigning to it."（`$` 前缀目标追加 Tip 段 "must not start with \"$\""）；目标非数值 → "Expected a number, but assignment target variable \"{foo}\" has evaluated to a string."；右值非数值 → "For \"#assign\" assignment source: Expected a number, but this has evaluated to a string: ==> 'a'"（blamed 表达式保留单引号源码）
  - **assertFails messageRegexp 补大小写不敏感**：Java `Pattern.CASE_INSENSITIVE`（AssertFailsDirective.java:59-61），Rust 侧漏了 (?i) 标志——修复后 string-builtins3 的 'expected'/'none' 等正则断言全部生效
  - **string-builtins1 归因 NOT_APPLICABLE**：substring 等缺口修复后首个未捕获错误为 `?new`（Java 特有）；**string-builtins3 定位为 jython25 弃用模块的过期断言**——`-1?lower_abc` 按 FTL 文法解析为 `-(1?lower_abc)`（jar 实测错误 "For \"-...\" right-hand operand: Expected a number..."），其 messageRegexp '0|at least 1' 与真实 Java 引擎矛盾（Probe26 复现套件校验逻辑），golden.rs 已注明原因；jython25 模块无构建文件，已从 Gradle 构建移除

## 7. 结论
