# 03 - 解析器迁移设计

## 1. 源与产物

- 语法源：`freemarker-core/src/main/javacc/freemarker/core/FTL.jj`（**4,845 行**）
- 生成方式：JavaCC **7.0.12**（`build.gradle.kts:102-104`：sourceDirectory=src/main/javacc，输出到 build/generated/javacc）
- 生成产物：`FMParser`（顶层入口 `FMParser(Configuration, Reader, ParserConfiguration)`，构造即解析 → `Template` 持有根 `TemplateElement`）
- Java 侧解析入口：`template/Template.java:247` `new FMParser(this, reader, actualParserConfiguration)`

> **Rust 方案**：手写递归下降解析器（对应全部产生式）。不引 pest/nom —— FreeMarker 词法有 5 个状态且指令/表达式上下文交织（如 `[#list]` 与 `${}` 的嵌套、`<#-- -->` 注释中的 NO_PARSE 状态），手写最可控。

## 2. 词法设计（对应 FTL.jj TOKEN 块）

### 2.1 五个词法状态（`DEFAULT` 之外的 state 声明）

| 状态 | 用途 | 进入方式 |
|---|---|---|
| `DEFAULT` | 模板文本扫描（找 `<`、`${`、`[#`） | 初始 |
| `IN_PAREN` | 指令参数区（括号内忽略部分 `<` 含义） | `<#if (a<b)>` 等 |
| `NO_SPACE_EXPRESSION` | 无空格表达式（`<#if x==y>` 紧贴） | 指令名后无空格 |
| `NAMED_PARAMETER_EXPRESSION` | 命名参数上下文 | `<#list ... as x = 1>` 等 |
| `NO_PARSE` | `<#-- -->` 注释与 `<#noparse>` 块内容 | 注释块 |

### 2.2 主要 token 清单（语义要点）

- 结构：`OPEN_TAG(<)/CLOSE_TAG(>)/OPEN_BRACE(${)/CLOSE_BRACE(})/OPEN_BRACKET([#)/SLASH(/)`
- 指令：`DIRECTIVE_END(/>|>)`、`IN`、`AS`、`USING`、`EQUALS`、`COMMA`、`SEMICOLON`、`DOT`、`ELLIPSIS`、`PLUS_PLUS/MINUS_MINUS`（宏循环变量 `+1` 语法）
- 运算符：`PLUS/MINUS/TIMES/DIVIDE/PERCENT`、`DOT_DOT(..)/DOT_DOT_LESS(..<)/DOT_DOT_ASTERISK(..*)`、`AND/OR`、`NOT`、`EQUALS_EQUALS(!=)/NOT_EQUALS/GT/LT/GTE/LTE`（含 `<#if>` 内 GT/LT 歧义消解）、`LAMBDA_ARROW(->)`
- 字面量：`STRING_LITERAL`（单/双引号、反斜杠转义、`\uXXXX`）、`NUMBER_LITERAL`（`1e3/1.5/0x1A`、尾部 `L/D/F` 标记）、`IDENTIFIER`（含非 ASCII、`$` 开头转义）、`BUILT_IN(?name)`、`COMMENT`、`HASH_HASH(##)`（宏参数可选标记）
- 表达式注释：`EXPRESSION_COMMENT` 状态内 `<#--  -->` 嵌在表达式中

### 2.3 词法特殊规则（易错点，须复刻）

1. **`<` 歧义**：模板文本中 `<` 只有后跟 `#`、`@`、`/`、`--`、字母时是标签开头；否则为文本（如 `a < b` 原样输出）。
2. **`${` 与 `$`**：`$${` 转义为字面 `$`+插值开始；`$` 后非 `{` 为普通文本。
3. **`[#` vs `[`**：`[#` 是方括号指令语法（`[#if]`、`[#assign]`、`[#ftl]`）；`[` 后非 `#` 为列表字面量上下文（表达式状态）。
4. **注释**：`<#-- ... -->` 在 DEFAULT 与 IN_PAREN/NO_SPACE_EXPRESSION 均可出现（NO_PARSE 状态）。
5. **字符串插值**：`StringLiteral(boolean interpolate)` —— 双引号串内 `${expr}` 插值，反斜杠转义规则含 `\n \t \\ \' \" \uXXXX`。
6. **数字后缀**：`1L`(long)、`1F`(float)、`1D`(double)、`1B`(bigdecimal)、`1e3`；无后缀默认 `BigDecimal`（十进制含 `.`/`e`）或 `Integer`/`Long`（整数）。
7. **指令名大小写不敏感**（`<#IF>` 合法），变量名大小写敏感。
8. **whitespace stripping**：解析期标记"可剥离"文本块（首行/尾行规则），渲染期执行（见 08 文档 §5）。
9. **`[#ftl]` 头部**：仅允许出现在模板首行（TRIVIAL_FTL_HEADER 产生式），设置 `encoding/attributes`（如 `[#ftl encoding="UTF-8"]`）。

## 3. 表达式产生式全映射（24 个）

Java 产生式（FTL.jj）→ Rust 函数签名（递归下降）→ AST variant：

| FTL.jj 产生式 | Rust 函数 | AST（expression.rs） |
|---|---|---|
| `Expression()` | `fn expression(&mut self) -> Result<Expression, ParseError>` | `Expr`（enum 根） |
| `PrimaryExpression()` | `fn primary(&mut self)` | —（调度） |
| `AtomicExpression()` | `fn atomic(&mut self)` | `Literal`/`Identifier`/`Paren`/`Lambda`/`BuiltinVar` |

| `UnaryPlusMinusExpression()` | 同上合并 | — |
| `AdditiveExpression()` | `fn additive(&mut self)` | `Add(Box,Box)`/`Concat`（字符串 `+` 走 AddConcatExpression 语义） |

| `EqualityExpression()` | `fn equality(&mut self)` | `Eq/NotEq` |
| `RelationalExpression()` | `fn relational(&mut self)` | `Gt/Gte/Lt/Lte` |
| `RangeExpression()` | `fn range(&mut self)` | `Range{start,end,kind}`（`..`/`..<`/`..*`） |
| `AndExpression()` | `fn and(&mut self)` | `And(Box,Box)` |

**附加**：`MethodCall`（`expr(args)`）、`BuiltinVariable`（`true/false/now/...` 内置变量）、`Identifier` 的 `!`/`!!`/`?` 后缀链、`f!` 函数引用（UnifiedCall 解析）。

## 4. 指令产生式全映射（13 个 + 头部）

| FTL.jj 产生式 | 指令 | AST（element.rs） |
|---|---|---|
| `If()` | `<#if>` | `If{cond, then, else}` |

| `Nested()` | `<#nested>` | `Nested{caller, count?}`（宏体回插） |

**FreemarkerDirective 内部分发清单**（指令名 → AST 节点）：
`include/import` → `Include{...}`；`assign/global/local` → `Assignment/BlockAssignment`；`if/elseif/else` → `ConditionalBlock`（`If` 语法糖）；`switch/case/default` → `SwitchBlock/Case`；`list/items/sep/else` → `IteratorBlock/Items/Sep/ElseOfList/ListElseContainer`；`attempt/recover` → `AttemptBlock/RecoveryBlock`；`escape/noescape` → `EscapeBlock/NoEscapeBlock`；`autoesc/noautoesc` → `AutoEscBlock/NoAutoEscBlock`；`outputformat` → `OutputFormatBlock`；`compress` → `CompressedBlock`；`break/continue` → `Break/ContinueInstruction`；`return` → `ReturnInstruction`；`stop` → `StopInstruction`；`flush` → `FlushInstruction`；`trim` → `TrimInstruction`；`nested` → `BodyInstruction`；`visit/recurse` → `VisitNode/RecurseNode`；`fallback/on` → `FallbackInstruction/On`；`setting` → `PropertySetting`；`transform` → `TransformBlock`；`macro/function` → `Macro`；`comment` → `Comment`；`noparse` → 特殊文本块；`ftl` → `FtlHeader`；`t`/`lt`/`gt` 文本转义；`new` → `NewBI` 表达式；`interpret` → `Interpret`（动态解析）。

## 5. AST 通用属性

每个 AST 节点携带（对应 `TemplateElement`/`Expression` 基类）：

```rust
pub struct Span { pub begin_line: u32, pub begin_column: u32, pub end_line: u32, pub end_column: u32 }
// Java: getBeginLine()/getBeginColumn()/getEndLine()/getEndColumn()
// 错误消息 "TemplateElement at line X, column Y" 依赖此数据
```

## 6. 解析错误行为

- `ParseException`/`UncheckedParseException` 语义：报错消息格式
  `Parsing error in template "name" at line X, column Y. <详细描述>`（错误消息内部含 token 上下文）
- JavaCC 的"期望 token 集"报错在 Rust 中改为"期望产生式名"列表（消息对齐策略见 09 文档 §4）。
- 错误恢复：Java 版解析失败即抛（无恢复）；Rust 保持一致——失败返回 `Err(ParseError)` 带最远位置信息。

## 7. 验收标准（P1）

1. `testcases.xml` 全部模板可解析（parse-only 模式，不渲染）。
2. 解析错误场景（`malformed` 类用例）错误消息与 Java 一致（模板名/行/列/期望清单）。
3. `[#ftl]`、`<#-- -->` 注释、`${}` 插值、`[#...]` 方括号语法、`<@macro/>` 自闭合、字符串插值、lambda、范围表达式等边界用例通过。
4. AST dump（`?dump`/调试视图）与 Java `FreeMarkerTree` 输出结构一致（P6 打磨项，P1 仅结构对齐）。
